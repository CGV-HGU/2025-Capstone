## 오늘 실험 순서

1. **실차 파일럿과 첫 bag 확인.** 새 기동·재사용 모두 이전 목표 종료, 신선한 odom·scan·TF, 정지와 리셋 뒤 원점·yaw를 확인한다. 짧은 파일럿 두 회차 사이에 `/cmd_vel`과 목표 종료를 대조하고, 두 번째 회차의 리셋 전에 별도 경량 녹화를 켠다. 이상이 재현되면 해당 회차와 시각을 남기고 다음 목표를 보류한다. 첫 주행 bag은 종료·압축 후 실제로 열어 RGB·scan·odom을 디코딩한다. [리셋 구간 진단 bag 명령](2026-11-27_odom_reset_plan.md#리셋-구간-진단-bag) · [odom·목표 종료 검증 계획](2026-11-27_odom_reset_plan.md)
2. **세 번째 장소는 인공조명 조건의 5열람실.** 10 m 출발점·목표점과 우회 폭을 표시하고, 바닥과 점등 상태를 사진으로 남긴다. 로봇 PC의 로컬 `~/ros2_ws/class5.sh`는 전방 10 m 목표를 보내고 `class5_01`부터 순서대로 회차를 저장한다. 현장 CSV에는 같은 회차 ID와 환경 ID `indoor_artificial`, 해당 배치 `S1` 또는 `S2`를 기록한다.
3. **배치와 반복.** `S1`은 박스 하나, `S2`는 같은 박스와 의자다. 장애물이 직진 경로를 막고 우회할 공간이 있도록 두고, 표시와 사진을 남긴다. 각 조건에서 두 배치를 섞어 반복하고 실제 순서를 기록한다. 계획 기준은 조합당 10회이며 80회는 저장량과 일정 산정을 위한 값이다. 시간이 제한되면 8개 조합을 먼저 고르게 채우고, 판정이 적거나 실패가 반복된 조합을 보강한다. 같은 설정으로 반복하고 바뀐 회차는 새 설정 ID로 기록한다.

팀이 알려준 팔각정과 기존 분석 문서에서 뉴턴홀 4층 사진으로 분류한 보관 자료는 장소와 회차를 대조한 뒤 연결한다. 기존 사진만으로 낮·밤의 정식 회차를 등록하지 않는다. [보관 사진의 위치 대조](../analysis/README.md#기준-장소와-낮-주행-기록)

**오늘의 분석 범위**는 관측한 환경 조합에서의 회피다. 조명은 시간·점등·창·그림자로 기록한다. 광량을 별도로 재지 않았다면 수치화된 밝기 차이나 조명 단독 효과를 주장하지 않는다. 물리 2D LiDAR 없이 4조건을 우선 진행한다. D1 거리 클립은 근거리 미검출이 반복돼 원인 분리가 필요하거나 독립 거리 정확도 비교를 하기로 할 때 추가한다. [기존 심사와 대응 범위](2026-11-27_JINT_submission_strategy.md#기존-심사-의견에-대한-대응)

## 현장에서 꼭 남길 기록

**장소·배치 최초 세팅**

- [ ] 장소·조건 ID, 날짜/시각(KST), 바닥 재질·색·광택, 실내등과 자연광 상태, 통로 폭 및 남은 우회 폭
- [ ] 실측 10 m 출발점과 목표점, 차체 기준점과 시작 방향, 목표 구역 크기, 공통 종료 기준, 박스·의자 크기 및 배치 좌표, 전체 배치 사진. 원고의 목표 반경 제안값은 0.50 m다. 제한시간을 두는지와 수동 중단 기준을 정해 확정값을 기록한다.
- [ ] 실제 설치본·펌웨어와 실행 인수, 모델·LUT·보정 파일의 해시, 카메라 광학 중심 높이·기울기, `base_link → lidar_link`의 TF, local/global costmap의 inflation·차체 반경·속도 설정. PC 체크아웃 YAML의 참고값은 inflation 0.65 m, robot radius 0.40 m, cost scaling 2.7이며 실제 적용값을 확인한다.

**매 회차 종료 직후**

- [ ] 고유 회차 ID, `pilot`/`main`, 환경 ID, `S1`/`S2`, 실제 순서·시간·설정 ID. rosbag과 결과 JSON에 같은 회차 ID를 붙인다.
- [ ] 종료 전에 **실제 목표 반경에 도달**했고 **장애물 접촉·수동 개입이 없었는지** 판정하고 관찰자 또는 외부 영상 ID를 기록한다. `Nav2 succeeded`·odom 거리·경과 시간은 별도 진단 자료로 기록한다. 실패·중단·보행자 등장·기록 누락도 그 이유와 함께 한 행씩 남긴다.
- [ ] 녹화 종료 뒤 bag과 결과 JSON 확인. 주행·실패 분석용 데이터는 RGB, `/scan`, `/odom`, `/cmd_vel`, `/tf`·`/tf_static`, `/plan`·`/local_plan`, local/global costmap 및 `/rosout`이다. 경로가 생성되지 않았으면 건수와 상황을 남긴다. Nav2 action 토픽은 판정 필수 자료에서 제외하고, 목표 종료는 JSON과 로그에서 확인한다.
- [ ] Figure 4용으로 조건별 **S1 우회 직전** 장애물 전체·바닥 접점과 통로가 보이는 RGB 프레임을 찍고 bag ID·초를 적는다. 대표 성공/실패도 회차 ID와 접근·회피 또는 정지 시각을 표시한다. 실제 도달 판정이 필요한 경우 외부 고정 카메라에서 목표 구역과 차체가 함께 보이게 촬영한다.

## 로봇 PC에서 실행과 저장 확인

로봇 PC에서 `~/ros2_ws` 기준으로 실행한다. `scripts/run_trial.sh`는 오늘 확인한 PC에 실행 가능한 로컬 파일로 있고 Git의 추적 대상에 없다. `record_rosbag.sh`, Nav2 YAML 등에도 현장 로컬 변경이 있다. 아래는 그 PC의 실제 인터페이스로 확인한 예시다. `--keep-bringup`으로 재사용할 때 적용된 스택·런치 값도 확인한다.

```bash
cd ~/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
scan_x_offset=-0.55  # 실험에서 확정한 값
goal_timeout=0       # 클라이언트 시간 제한을 두지 않는 경우. 공통 설정에 맞춰 조정
config_file=~/data/jint/field_config_01.json  # 새 설정에는 새 파일명 사용
python3 JINT/analysis/trial_records.py snapshot --installed \
  --output "$config_file" --camera-calibration ~/data/cam/usb_webcam.yaml \
  --lidar-x-offset "$scan_x_offset"

# 파일럿을 마친 뒤 진행하는 본 주행 예시
trial_id=indoor_artificial_s1_01
./scripts/run_trial.sh --name "$trial_id" --mode nav -x 10.0 -t "$goal_timeout" \
  --lidar-x-offset "$scan_x_offset" --keep-bringup --no-rviz

bag=~/data/bags/nav_$trial_id
result=~/data/trial_outcomes/$trial_id.json
python3 JINT/analysis/trial_records.py check --bag "$bag" --result "$result" --trial-id "$trial_id"

# 관찰자가 실제 도달·무접촉·무개입을 확인한 성공 회차 등록 예시
python3 JINT/analysis/trial_records.py add \
  --field-log ~/data/jint/field_log.csv --trial-id "$trial_id" \
  --phase main --environment indoor_artificial --layout S1 --configuration "$config_file" \
  --bag "$bag" --result "$result" \
  --observed-outcome success --goal-check '현장 관찰자가 제한시간 안에 표시된 목표 구역 도달 확인'
```

실패는 관찰에 따라 `collision`, `timeout`, `nav_abort`, `manual_intervention`을 사용한다. 평가 자체가 불가능한 시도는 `invalid`와 `--invalid-reason`을 남긴다. 판정이 아직 안 되면 `--observed-outcome`을 생략해 등록하고 확인 후 CSV를 채운다. 파일이 없는 경우에는 해당 파일 인수를 생략하고 그 사유를 기록한다. 관찰자·외부 영상 ID·보행자 등은 CSV의 해당 열과 `notes`에 적는다. [현장 CSV 양식](../../paper/review/planning/templates/field_log.csv) · [기록 사용법](../analysis/README.md#현장-csv의-자동-기록과-집계)

**저장과 공유**는 조건 단위로 진행한다. 15:28 KST 로봇 PC 가용 공간은 약 98 GiB이고, 지난 파일럿 압축 bag은 회당 0.85–2.08 GB였다. 압축이 끝나면 별도 저장장치에 조건별 bag·CSV·JSON·설정 사본을 만들고 해시를 검증한다. 외부 영상과 배치 사진도 같은 회차·조건 ID로 보관한다. Git에는 원고·분석과 보관 자료 ID를 올린다. [저장 용량과 백업 명령](../analysis/README.md#본-주행-저장-공간)

## 실험 후 팀에 넘길 내용
