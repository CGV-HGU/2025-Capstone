# 별도 ICCAS–IJCAS 저장소의 원고 확인과 실험 계획 보정

작성일: 2026-11-18. 사용자가 제공한 `https://github.com/CGV-HGU/ICCAS-IJCAS-2026.git`를 직접 내려받아 확인했다. 기존 2025-Capstone의 원고·코드·로봇 점검과 연결하는 문서다. **새 저장소의 원고/그림은 변경하지 않았고, 새 실험·추론도 수행하지 않았다.**

## 1. 동기화와 점검 범위

- 기존 Documents/GitHub에서 같은 remote를 사용하는 복제본을 찾지 못해 `/storage/emulated/0/Documents/GitHub/ICCAS-IJCAS-2026`에 새로 clone했다.
- 이어 `git pull --ff-only`를 실행해 최신 상태임을 확인했다. 브랜치는 `main`, 로컬/원격 HEAD는 `078bffca970a715b80542284daf65000d18c777d`다. 커밋 제목은 `Finalized Paper`, 날짜는 2026-09-23이다. 원격 branch 조회 결과도 `main` 하나다.
- 현행 `paper/IJCAS` LaTeX 492행 전체와 `paper/ICCAS` 118행 전체를 읽었다. IJCAS의 본문 그림 7개도 직접 보았다. IJCAS 원고의 SHA256은 `eed49d8fb606a8dde29e80889aa9e36e378380d7cbfdf9b11ec1d76e87ca915b`다.
- IJCAS 본문에는 그림 7개, 표 3개(기호/설정/거리 결과), 참고문헌 항목 30개가 있다. 문헌 키/그림·표 참조의 내부 연결과 그림 파일 존재를 확인했다. 참고문헌 30편의 내용·서지정보를 모두 외부 검증한 것은 아니다.
- 현행 IJCAS 본문 PDF는 저장소에서 찾지 못했다. LaTeX 컴파일러가 없어 새 PDF를 빌드하지 않았으며, 완성 PDF의 페이지 배치·줄넘침 검토는 미실행이다. 본문과 그림 검토는 실제 `.tex`와 이미지 원본으로 수행했다.
- 이 폴더에 IJCAS 형식의 우리 원고가 있다는 사실은 확인했다. 이 파일이 과거 심사에 제출된 파일과 바이트 단위로 동일한지는 제출 이력 없이 확정할 수 없다. 사용자가 제공한 심사평의 출처는 기존 지시대로 IJCAS AE로 취급한다.

## 3. 이 IJCAS 원고가 실제로 평가한 것

### 정적 거리 실험: 264~320행

- 기준 거리 2.50m, 방위 0°/+20°/−20°.
- 정면은 박스, 왼쪽은 사람, 오른쪽은 쓰레기통. 정적 실험에는 이미 물체 3종이 있다.
- 정면 바닥 잡음 있음/완화 후, 왼쪽, 오른쪽의 네 조건에 각 `N=25`가 기재돼 있다. 약 45초 동안 취득했다고 기술하며, 그림은 최초 10개 표본이다.
- 표의 평균 거리/표준편차는 각각 2.239/0.172m, 2.718/0.008m, 2.583/0.011m, 2.663/0.000m다. 평균 오차는 −0.261/+0.218/+0.083/+0.163m다. 이번 점검은 본문·표 확인이며 원시 25개 값의 재계산은 아니다.
- 줄자 ±1cm, 회전대·각도기 ±0.5°라고 기술돼 있다. 실제 측정 기록·기기 사양을 추가로 확인해야 한다.

**해석:** 정적 실험을 ‘박스 하나만 평가’했다고 요약하는 것은 부정확하다. 다만 방위마다 물체가 달라 물체 형상·대비와 방위의 효과가 섞인다. 같은 물체를 여러 거리/방위에서 평가하는 v2 D1 설계는 여전히 유효하다.

### 주행 실험: 323~382행

- OMO R1v2, Intel Core Ultra 7 155H/32GB, LX-V11 카메라, Stella VSLAM, ROS 2/Nav2.
- 광택 바닥과 창가·천장 조명이 있는 10m 직선 경로, 정지 박스 하나.
- 50회 중 39회 성공(78%). 실패 11회 중 8회는 segmentation jitter, 3회는 회피 후 너무 이른 경로 복귀로 설명한다.
- 대표 주행 화면 3장과 마스크 오류 예시가 있다. 전체 궤적, 조건별 반복 결과표, 외부 baseline의 정량 비교는 없다.

**해석:** 현재 추가 실험의 중심은 여러 장소/복수 장애물에서의 **폐루프 주행**, 실패의 정량 기록, 고정한 개선 방법의 재검증이다. 새 물체 사진이나 성공 화면만 추가해서는 이 공백이 채워지지 않는다. 실패 8/3 분류의 근거도 과거 50회 원자료와 연결해야 한다. 로봇에서 읽은 다른 20회 bag은 50회 원본과 자동으로 연결되지 않는다.

### 학습 데이터에 관한 새 정보

원고가 지목한 출처는 [Roboflow Floor Segmentation 프로젝트](https://universe.roboflow.com/projects-aw2cm/floor-segmentation-wesrg)다. 2026-11-18 검색에서 제공된 이 프로젝트 요약에는 `Floor` 한 클래스와 여러 데이터 버전이 표시됐다. 이는 이번에 확인한 `person/floor` 두 클래스의 현재 체크포인트와 바로 일치한다고 볼 수 없다. 프로젝트/버전의 후속 변경, 별도 재라벨링 또는 추가 학습이 가능하므로 틀린 출처라고 단정하지 않는다. 실제 사용한 export의 `data.yaml`과 학습 이력이 필요하다. 공개 페이지의 배포 모델 지표를 우리 YOLO 모델의 성능으로 사용해서도 안 된다.

현재 파일: [체크포인트 메타데이터](../../experiments/logs/pc_extracted/yolo11n_seg_checkpoint_meta.json), [OpenVINO 클래스 정보](../../src/freespace_detection/scripts/best_openvino_model/metadata.yaml).

## 6. 앞서 제안한 계획의 유지·변경

1. **유지:** 관측·측정 오류 정리 후 설정을 고정하고 새 평가를 수행한다. 3장소×2배치×10회=60회와 D1/D2 36클립은 자원에 따른 미실행 제안이다. 이번 원고를 읽었다고 그 숫자가 저널의 충분 조건이 되지는 않는다.
2. **설명 수정:** ‘정적 장애물 종류가 하나’가 아니라 ‘정적 거리 실험에는 여러 물체가 있으나 주행 조건이 하나’다. 장소·복수 장애물·실패의 폐루프 검증을 우선한다.
3. **설명 수정:** 학습 자료 URL은 이 원고에 이미 있다. 남은 것은 실제 버전/분할/클래스/가중치의 재현 연결이다.
4. **추가:** IJCAS 결과표의 평균 편향과 결론의 최대 오차처럼 읽히는 문장을 맞춘다. 기존 25개 원시값과 50회 trial 기록이 확보되면 재집계를 먼저 한다.
5. **유지:** 물리 2D LiDAR 확보는 선행 조건이 아니다. 현재 IJCAS도 이미 제한된 환경의 거친 장애물 관측이라는 보수적인 주장을 사용한다. 이 주장 아래 적절한 외부 시각 baseline을 검증하고, 물리 비교는 실제 장비와 최종 주장에 따라 선택한다.
6. **그림 보정:** 기존 pipeline·실험 사진·성공 screenshot을 늘리는 데 시간을 우선 배정하지 않는다. 전체 주행 궤적/결과, 동기화 실패 원인, 동일 배치 조명 비교, 외부 baseline 분포, 필터의 jitter–미검출–지연 관계를 새 그림으로 우선한다. 정적 polar plot 최초 10장은 전체 정량 분포/표로 보완한다.

**후속 구현 전 핵심 정보:** IJCAS 25표본 원본과 50회 결과 기록, 사용 학습 데이터 export/버전, 과거/새 평가의 실제 코드 설정, 현장 인원·일수·장소 접근. 기존 [통합 계획](planning/04_Robot_Checked_Code_and_Experiment_Plan_20261118.md)의 준비 통과 기준을 그대로 적용한다.

## 7. 이번 점검의 한계

이 문서는 **우리 IJCAS 형식 원고**를 직접 읽은 점검이다. IJCAS에 게재된 유사 연구 여러 편을 정독해 저널의 실험 수준을 비교한 문헌 검토는 여전히 수행하지 않았다. 작성된 실험 수치의 원자료 재현, 저널 채택 가능성, 실제 과거 제출본 동일성도 이번 저장소 확인만으로 확정하지 않는다.
