> **별도 IJCAS 원고 확인 후 갱신:** [ICCAS–IJCAS 저장소 본문 점검](../10_IJCAS_Manuscript_Repository_Check_20261118.md)을 함께 적용한다. `ICCAS-IJCAS-2026/main@078bffc`의 실제 IJCAS 원고와 그림 7개를 읽었다. 정적 거리 실험에는 이미 사람/박스/쓰레기통이 있고 주행 실험은 한 박스 39/50회다. 학습 데이터 URL도 기재돼 있다. 추가 검증의 초점은 주행 조건 확장·실패 개선·외부 비교이며, 학습 버전/가중치 연결과 평균 오차의 표현을 보완한다. 아래 60회/36클립은 여전히 미실행 제안이다.

## 1. 판단

우선순위는 **관측·측정의 오류 정리 → 같은 영상에서 필터 검증 → 설정 고정 → 서로 다른 조건에서 반복 주행**이다. 현재 투영 계산은 이미 NumPy로 벡터화돼 있다. 먼저 모델을 교체하거나 스캔 부분을 다른 언어로 다시 쓰는 것보다 클래스 처리, 장애물 소실/지연, 오래된 관측, 공정한 측정 문제를 해결하는 편이 근거가 강하다. 개선량은 아직 측정하지 않았다.

권장 현장 범위는 **3장소×2배치×10회=60회**와 **정적 36클립**이다. 60회는 제안 방식 하나의 주행이다. 외부 baseline의 폐루프 주행을 포함한 숫자가 아니다. 36클립은 주행 36회가 아니라 정지 상태의 짧은 영상 취득이다. 사람 수·사용 가능 일수는 미확정이며 현장 2명, 준비 이후 3~4일을 잠정 가정한다. 분석·코드 보완·원고 작업 시간은 별도다.

IJCAS AE의 핵심은 단일 장면, 실패, 광택/조명 민감도, 외부 비교의 근거 부족이다. 이를 직접 보완하는 설계이며 채택을 보장하지 않는다. 관측 범위가 제한된 단안 카메라 기반 장애물 회피라는 기여를 명확히 하고, 결과보다 넓은 LiDAR 대체 주장은 피한다. 학습 자료 출처·분할·독립 평가와 방법의 설명도 함께 보완한다.

### 필터 후보는 어떻게 고를 것인가

1. 위 개발용 영상에서 박스 접근·의자 다리/카트·반사광·회전·가림 구간을 먼저 정하고 표본 선택 규칙과 수동 경계 정답을 남긴다. 같은 연속 장면의 인접 프레임을 서로 독립된 표본으로 세지 않는다. 전체 floor IoU와 함께 하단 장애물 경계/미검출을 본다.
2. 클래스/시각 처리는 정확성 수정으로 공통 적용한다. 공간 필터만 원본/5×5 1회/7×7 2회를 비교한다. 그다음 공간 필터를 고정하고 시간 필터 없음/현재/비대칭 후보를 비교한다. 모두 개발 자료에서 수행하고 끝없이 조합을 탐색하지 않는다.
3. GT가 있는 표적 구간의 거리 오차, GT가 없는 구간의 경계 오류, 정지 장면의 jitter, 검출·해제 지연을 구분한다. GT 없는 기존 영상으로 절대 거리 MAE를 새로 만들지 않는다.
4. 최종 후보와 선택 규칙을 고정한 후 새로운 정적/주행 평가를 취득한다. 새 평가 결과를 보고 파라미터를 바꾸면 새 버전의 평가로 분리한다. 오프라인 출력 개선은 폐루프 성공률 개선의 증거로 사용하지 않는다.

기존 20회는 9월 21일이고 마지막 주요 필터 변경은 10월 1일이다. 따라서 그 20회로 현재 필터의 성공/실패 원인을 단정할 수 없다. 과거 78%와 새 장소 결과의 차이를 코드 개선의 인과 효과로 주장하려면 동일 조건의 별도 전후 대조가 필요하다. 최소안에서는 현재 고정 버전의 성능 검증으로 한정한다.

| A | 균일한 조명, 반사가 비교적 적은 실내 직선 공간 | 기본 조건에서 박스와 복수 장애물을 회피하는가 | 충분한 우회 폭과 측정 가능한 시작/목표, 학습 자료와의 중복 여부 |
| B | 광택 바닥과 창가/반사광이 있는 공간 | AE가 지적한 광학 조건에서 어떤 오류가 생기는가 | 밝기·노출·광원 방향과 바닥 사진. 장소만 바뀐 비교는 조명 단독 효과로 해석하지 않음 |
| C | 다른 바닥 재질·배경 또는 다른 폭의 실내 공간 | 공간이 달라도 고정 설정이 유지되는가 | 지나갈 수 없는 폭은 제외. 오석 코너 후보는 우선 예비 검증하고, 회전 기능이 확인되지 않으면 직선 구간을 선택 |

비슷한 복도라도 바닥·조명·배경이 다르고 독립된 평가 장소라면 의미가 있다. 다만 장소 이름만 달라서는 환경 범위가 크게 늘지 않는다. **차이가 거의 없는 세 번째 장소 대신 두 장소에서 재질/조명·장애물 조건을 더 충실히 평가할 수 있다.** 그 경우 v1을 그대로 자동 채택하지 말고 새 조건표를 본 평가 전에 확정한다. ‘장소 3개’는 통계적 임계값이 아니다.

모든 장소에서 모델/카메라 높이·틸트/투영/필터/Nav2 설정을 고정한다. 장소별 지도와 시작·목표는 허용하되 작성 방법을 기록한다. 지도에는 평가용 임시 장애물을 미리 넣지 않는다. 지도·wheel odom·VSLAM 사용을 공개하고 ‘카메라만으로 모든 내비게이션을 수행’했다고 확장하지 않는다. 새 장소에서 모델을 다시 학습하지 않으며, 불가피한 설정 변경은 별도 평가다.

각 장소가 원래 학습/검증 영상에 포함됐는지도 원자료로 확인한다. 확인 전에는 미학습 장소의 일반화 성능이라고 쓰지 않는다. 가능하면 B/C에 학습·개발에 사용하지 않은 장소를 포함하고, 프레임 단위 무작위 분할로 인접 장면이 학습과 평가에 섞이는 것을 피한다.

### 배치·횟수·순서

| 배치 | 잠정 좌표: 시작을 (0,0), 전진 +x | 반복 |
| --- | --- | ---: |
| S1 | 단일 박스 중심 (4.5, 0)m, 목표 (10,0)m | 장소마다 10회 |
| S2 | 박스 중심 (3.5,+0.35)m와 의자 또는 카트 중심 (7.0,-0.35)m, 목표 (10,0)m | 장소마다 10회 |

총 `3×2×10=60회`. S2 물체는 동일 실물을 정해 전 장소에서 사용하고 실제 폭·깊이·높이를 기록한다. 중심 좌표와 별도로 물체 경계·로봇 몸체의 통과 여유를 측정한다. 좌표는 예비 실험 전 제안이며 통로/회전 반경이 허용되는지 확인한 후 고정한다. S1/S2는 수와 형상이 함께 바뀌는 범위 평가다. 둘의 차이를 장애물 개수 하나의 효과로 해석하지 않는다.

[v2 주행 계획표](templates/proposal_v2_20261118/trial_plan.csv)에 각 장소 10개 block, block당 S1/S2 각 1회를 고정 난수 seed로 섞어 두었다. 모든 행은 `planned`다. 실제 순서는 따로 기록하고 조명·배터리·위치 변화를 남긴다. 반복 사이의 시작 자세, 로봇/물체 위치, costmap 초기화 절차를 통일한다. 성공한 10회가 채워질 때까지 반복하는 방식은 사용하지 않는다.

### 결과 판정

- 주 결과: **Nav2 성공 + 외부 확인 목표 오차 기준 충족 + 접촉 없음 + 수동 개입 없음**을 모두 만족. 목표 위치 오차 0.25m, timeout 120초를 잠정 제안하며 예비 실험 후 본 평가 전에 고정한다. yaw 허용오차도 goal checker와 일치시켜 기록한다.
- 시간: 목표 수락부터 최종 결과/취소까지. 실제 움직임 시작부터의 시간은 보조 지표로 따로 저장한다. 기존 목표 스크립트 기본 timeout은 60초이므로 제안값이 자동 적용됐다고 생각하지 않는다.
- 분류: 성공/접촉/timeout/Nav2 abort/수동 개입. 복합 사건은 원시 플래그를 모두 보존하고 표의 우선순위를 사전 고정한다. 접촉·막힘·개입을 데이터 손실 사유로 제외하지 않는다.
- 시스템 실패를 포함한 전체 시작 시도를 보존한다. 외부 방해·기록 장치 고장 등 제외 사유가 있으면 원래 행과 재시도를 모두 남기고 전체 시도 수/평가 포함 수를 함께 보고한다.
- 조건별 성공 수/전체 수와 95% Wilson 구간을 제시한다. 10회는 넓은 불확실성을 갖는다. 예를 들어 10/10이어도 구간 하한은 약 72.2%다. 충분성을 과장하지 않는다. 같은 장소의 반복을 서로 다른 환경 10개로 세지 않는다.
- odom 경로 길이·정지 시간은 보조 지표다. 실제 접촉/최소 몸체 여유는 외부 영상·물체 위치 측정으로 확인한다. 최단 scan이 2.18m 이상이라는 사실로 로봇의 실제 여유 거리를 주장하지 않는다.

실패 재현은 원인을 식별할 수 있도록 영상·costmap·계획·명령·진단을 함께 본다. 기존 run08/12와 비슷한 정지가 나타나면 최근 관측 시각, 실제 표적 검출, costmap 장애물/인플레이션, 유효 경로·속도 명령·odom을 같은 시간축으로 비교한다. 원인이 바뀔 수 있으므로 과거의 ‘유령 장애물’ 설명을 전제하지 않는다.

## 5. 정적 비교: 27개 거리·방위 클립 + 9개 조명 클립

### D1: 거리와 방위, 27클립

통제하기 쉬운 한 장소에서 같은 박스로 `3거리(2.5/3.5/4.5m) × 3방위(-20/0/+20°) × 3독립 재배치=27클립`, 각 8~10초를 제안한다. 여기의 거리는 사전에 정의한 scan 원점에서 물체 전면 기준점까지의 평면 방사 거리다. 로봇 중심에서의 전방 거리와 혼동하지 않는다.

각 거리·방위 조합의 배치 1은 보정 9클립, 배치 2·3은 평가 18클립이다. 매번 물체를 다시 놓고 실제 위치·측정 기준점·측정 방법과 불확실성을 기록한다. 보정/평가가 연속 영상의 프레임 분할이 되지 않게 한다. 이것은 한 장소의 거리·방위 평가이며 baseline의 장소 일반화 실험으로 쓰지 않는다.

### D2: 광학 조건, 9클립

광택 바닥의 같은 위치에서 `3새 배치 × 3조명 조건=9클립`을 별도로 찍는다. 물체는 3.5m/정면을 기준으로 두고, 각 배치에서 물체·카메라를 움직이지 않은 채 기준 조명/낮은 조명/창가 역광 또는 강한 반사광을 비교한다. 장소에서 만들 수 있는 조건을 사전 확정한다. 광원만 바꿀 수 없다면 복합 광학 조건 평가라고 명시한다.

auto exposure 사용 여부와 가능하면 exposure/gain을 남긴다. lux 측정 장비가 없으면 정량 조도 제어라고 쓰지 않는다. 이 9클립은 모델 보정·필터 선택에 사용하지 않는 독립 평가다. 같은 배치의 세 클립은 짝으로 분석하고 프레임 수를 독립 반복 수로 보고하지 않는다.

계획표: [36클립 목록](templates/proposal_v2_20261118/static_clip_plan.csv). 가까운 사각지대 내부 검출을 평가하는 설계는 아니다. 2.18m 아래는 기하적 관측 한계로 별도 설명한다.

### GT와 평가 단위

측정한 물체의 실제 footprint/전면 위치를 TF에 따라 scan 좌표계로 변환하고, 해당 표적과 교차하는 각도에서 동일한 거리 정의로 비교한다. 전체 scan 최소값은 벽을 잡을 수 있으므로 표적 거리로 대체하지 않는다. 중심점 거리 하나를 모든 각도에 정답으로 넣지 않는다. 보정에 사용하는 표적 위치와 평가 정답을 명확히 구분한다.

보고 항목은 유효 표적의 MAE/RMSE와 편향, 표적 미검출률, 빈 공간 오탐, 시간 변동, 처리 지연이다. 검출 성공 표본만 남겨 MAE를 낮추지 않도록 검출률과 평가 가능한 표본 수를 나란히 제시한다. 프레임별 분포는 보조 자료로 쓰고 불확실성 계산은 독립 배치/클립을 기준으로 한다.

## 6. 외부 baseline과 3D LiDAR

우선 기존 MiDaS Small과 Depth Anything V2 중 실제로 재현 가능한 최소 1개를 동일 RGB에서 평가한다. 가능하면 두 모델을 함께 사용하되 실행 오류를 임의 숫자로 채우지 않는다. 상대 깊이는 보정 9클립에서 한 번 정한 전역 scale/shift 등 명시한 방법으로 metric 변환하고 평가에서는 고정한다. 프레임별 GT 맞춤이나 평가 영상별 min/max 스케일링을 사용하지 않는다. 물리적으로 타당한 변환식과 손실/유효 범위는 보정 단계에서 확정한다.

동일 로봇·입력 원본·평가 표적·관측 영역·측정 조건을 사용한다. 모델 고유 입력 크기/전처리/정밀도와 실제 백엔드는 공개한다. 충분한 준비 실행 후 추론 시간과 영상 수신→마스크→scan 생성/발행 시간을 구분하고 p50/p95·새 관측률을 보고한다. 영상 header가 실제 노출 시각을 보장하지 않으면 이를 센서 전체 지연으로 부르지 않는다. GUI·녹화 부하도 기록한다.

이 최소안의 외부 비교는 **인식/측거/지연 비교**다. V-LiDAR 자체는 60회 폐루프 주행으로 검증한다. ‘다른 방법보다 주행 성공률이 높다’고 주장하려면 baseline scan을 같은 Nav2에 실제 입력하는 별도 주행이 필요하다. 필요 시 대표 두 조건×방법별 10회 같은 **추가 예산**을 별도 확정한다. 녹화된 궤적의 scan만 바꿔 재생하는 것으로 대체할 수 없다.

물리 2D LiDAR는 이번 선행 조건으로 두지 않는다. 3D 장비가 이미 안정적으로 준비돼 있다면 정적 장면의 보조 비교부터 검토한다. [공식 Humble 변환기](https://github.com/ros-perception/pointcloud_to_laserscan/blob/humble/README.md)로 TF·높이 범위·각도 범위를 고정해 투영할 수 있지만 **3D 점군의 2D 투영 비교**라고 표기한다. 원생 평면 LiDAR와 동일한 관측 방식·가격·전력의 비교가 아니다. 실제 모델·접근·작동 상태는 이번 점검으로 확정하지 않았다.

기존 **IEEE Access 버전**의 V-LiDAR MAE 0.192m와 현재 CSV 재집계 1.529m, 지연 12.9ms와 CSV 19.72ms 사이의 연결은 아직 없다. 서로 다른 버전일 수 있으므로 잘못된 수치라고 단정하지 않지만, 원자료·설정·집계 코드가 연결되기 전에는 새 비교표의 근거로 재사용하지 않는다. 별도로 확인한 IJCAS 원고에는 이 외부 비교표가 없다. [재집계 근거](../07_Post_Branch_Audit_and_IJCAS_Priorities_20261118.md)를 참고한다.

## 7. 반드시 남길 기록과 예비 실험 통과 기준

원본 RGB, 획득 header를 유지한 scan, 원시/필터 후 관측과 품질 진단, `/odom`, `/cmd_vel`, `/tf`, `/tf_static`, 전역/국소 경로, 실제 costmap과 관련 업데이트, 내비게이션 목표/수락/결과, 외부 영상과 접촉/개입 플래그를 trial ID로 연결한다. 정적 지도·카메라 보정·장착·물체 실측과 source/model/LUT/params 해시도 저장한다. 마스크를 매 프레임 저장할지, 정확히 같은 버전으로 재생성할지는 부하를 보고 결정하되 추론 설정과 입력을 보존한다.

Humble의 action 결과를 일반 `/goal_pose`만 기록해서 확보할 수는 없다. 기존 action client의 결과 callback에서 구조화된 파일을 저장하는 방법을 우선 검토한다. hidden status/feedback 토픽을 추가한다면 실제 존재·메시지·QoS와 기록 여부를 확인한다. 로거의 PASS 규칙으로 Nav2 결과를 대신하지 않는다.

예비 1회 후 **파일을 실제로 다시 열어서** RGB 디코딩, 시간 정렬, source version, 결과 로그, TF, 센서 만료 검출, 외부 영상 동기화를 확인한다. 녹화 중 프레임/scan 누락과 부하도 확인한다. 기존 raw RGB는 약 28MB/s 수준이었으므로 저장 공간을 미리 계산하고 압축률을 가정해 용량을 과소 산정하지 않는다. 로봇의 이번 여유 공간은 약 143GB(약 133GiB)였으며 실제 사용 가능량은 취득 직전 다시 확인한다.

본 평가 진행 조건은 다음과 같다.

1. P0 네 항목과 좌표/관측 영역 확인을 통과했다.
2. 버전·모델·설정·baseline 보정 절차·배치·판정 규칙을 고정했다.
3. 예비 기록을 다시 열어 분석 가능한지 확인했다.
4. 통로에서 실제 우회가 가능하고 외부 관찰자가 접촉/개입을 기록할 수 있다.

조건을 통과하지 못하면 본 평가를 시작한 것으로 세지 않고 준비 작업을 계속한다. 일정을 맞추려고 근거가 빠진 주행을 쌓지 않는다.

성공 시연 그림은 조건별 성공 시간 중앙값에 가장 가까운 회차처럼 선택 규칙을 둔다. 실패를 빼고 좋은 장면만 고르지 않는다. 최종 원고의 그림 수는 묶어서 줄일 수 있다. 11/16 미팅의 cap2 복구 궤적·RMSE는 별도 연구 자료이므로 V-LiDAR 결과로 사용하지 않는다.

이번에 만든 [20회 기록 진단 그림](../verification/robot_20261118/twenty_run_diagnostics.png)은 기존 데이터 상태를 보여주는 점검 산출물이다. 새 성능 실험 피규어나 성공률 그림이 아니다.

## 9. 단계별 일정과 범위 조정

| 단계 | 할 일 | 산출물/다음 단계 조건 |
| --- | --- | --- |
| 준비: 소요 별도 | P0 수정, 기존 영상 개발 평가, 보정·좌표 확인, 결과 수집 연결 | 버전 고정 후보와 분석 가능한 예비 기록 |
| 현장 1일차 | 장소 확정·실측, 예비 취득/개봉, D1/D2 36클립 | GT·split·설정·광학 조건 기록. 여유가 있으면 A 본 평가 시작 |
| 현장 2일차 | A와 B 주행, 조건 순서 교차 | 각 장소 20회와 누락 점검 |
| 현장 3일차 | 남은 B/C 주행 | 합계 60회의 전체 시도·결과·영상 연결 |
| 현장 4일차: 여유 | 장소 접근·날씨/광원·장비 문제 대응 | 빠진 조건 보충. 실패 회차를 지우거나 성공 회차로 교체하지 않음 |
| 분석: 소요 별도 | 고정 baseline/ablation 실행, GT 평가, CI·그림·원고·리뷰 대응표 | 각 주장과 원본/설정/집계 코드의 연결 |

현재 사용 가능 일수·인원·교수님 보고일은 미확정이다. 미팅의 11월 19~20일은 피드백 목표로 읽으며 이 모든 작업의 완료 기한으로 단정하지 않는다. 촉박하면 점검 근거와 실험 계획을 먼저 보고하고, 새 결과 완료일은 준비 단계의 통과 여부로 정한다.

우선 줄일 항목은 새 하드웨어 도입, 새로운 모델 다수 추가, 카메라 높이/틸트 대규모 변경, 추가 폐루프 우위 비교다. 측정 오류 정리·실패 기록·공정한 외부 비교·광학 조건 평가를 생략한 채 반복 수만 늘리지 않는다. 현장 자원이 줄면 서로 의미가 다른 두 장소와 핵심 장애물/조명 조건을 지키고, 변경된 반복 수와 불확실성을 공개한다.

## 10. 아직 필요한 정보

사용 가능 일수와 운영/관찰 인원, 실제 보고 목표일, 세 장소의 접근·바닥·폭·조명 상태, 거리 측정 기기, 평가 물체 크기, 학습 원본의 장소/분할, baseline의 재현 가능한 체크포인트·환경이 필요하다. 대부분 준비/예비 실험에서 확인할 항목이다. 3D 장비 모델·장착은 선택 비교를 진행할 때 추가로 확인한다.

현재 파일은 의사결정을 위한 구체적인 초안이다. 실제 구현·측정 결과나 저널 수용 가능성을 대신하지 않는다.
